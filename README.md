|------|----------|--------|

三个实验各用各的项目码，写在 `js/config.js` 的 `experiments` 映射里（`search → 8XKAVD`、`stroop → NQRU6M`、`ior → W2U4GB`），提交时按 `experiment` 自动路由，不需要手工切换。

### 被试码机制

- 首次进入时前端用 `crypto.getRandomValues` 生成 **8 位随机被试码**（如 `8MQV6XFE`，字母表 31 字符，去掉易混淆的 I/L/O/0/1），存进 localStorage `edu_admin_subject_code`，此后该浏览器永久复用。
- 码与浏览器绑定、与昵称解耦：两人都填「小明」也会拿到两个不同码，数据不会串号。
- `app.js` 提交时把 `U.subjectCode()` 写进 `participant` 字段，昵称只用于页面显示；任务打勾、查看结果都按这个码匹配云端记录。

> ⚠️ **代码与实际落库目前不一致**：首批实测数据里 `participant` 是 `P01`–`P06` 这样的顺序号，不是 8 位随机码，三个项目还各自独立编号。因此现在**做不了被试内的跨实验相关**。正式收数前必须查清是后端覆盖了字段，还是这批测试记录来自手工导入；这一条比多加被试更优先。详见「结果与讨论」的「跨实验的三个坑」。

### 结果云端重画

完成实验后，每个试次的原始数据随提交上传云端。「查看结果」按被试码拉回最近一次记录、重新聚合并绘图，而非只读本地缓存；云端不可用时回退本地缓存。眼动采样不参与重画，原因见文末说明。

## 运行方法

1. **含眼动（推荐）**：双击根目录 `start.cmd`，自动起 HTTPS 服务并打开浏览器。
2. **含眼动（手动）**：
   ```bash
   node server-https.js --open   # --open 可省略
   ```
   访问 `https://localhost:8443`（**必须是 https**）。首次会提示证书不受信任，点「高级 → 继续前往」；脚本自动生成 `.certs/` 下的自签名证书。
3. **无眼动**：直接双击 `index.html`，`file://` 下也能运行并上传数据，只是调不了摄像头。
4. 需要联网上传数据；**上传失败（含断网）时自动导出 CSV 兜底**，避免数据丢失。

> **为什么必须 HTTPS**：`getUserMedia` 只在安全上下文可用。用 `start.cmd` 或 `server-https.js` 启动后，页面会显示绿色「✓ 当前为安全上下文，摄像头眼动追踪可用」。
>
> **排障**：确认 ① 地址带 `s`；② 端口 8443 未被占用；③ 证书弹窗已点「继续前往」。
>
> **眼动流程**：勾选「启用摄像头眼动追踪」后先走**九点校准 + 精度验证**（约 1–2 分钟），通过才进实验；不勾选则完全跳过。校准阶段显示红点轨迹反馈，精度验证和正式实验阶段自动隐藏红点。校准点击会连续采集多帧预测、过滤 NaN 等异常帧，拿到稳定值才记录，以避免误差显示成 NaN、注视点乱飘。整个会话只初始化一次 WebGazer，后续实验用 `pause()` / `resume()` 复用，不会重复初始化 MediaPipe wasm。

## 实验设计（收数前定稿，含预测）

### 实验 1 · 视觉搜索（+ 心理旋转）
- **任务**：屏幕出现一组字母（目标 T + 干扰），尽快按键判断「目标 T 有没有出现」（有=F / 无=J）。
- **设计**：特征搜索（绿色 T 里找唯一的红色 T，颜色 pop-out，斜率≈0）vs 联合搜索（「红横 T + 绿竖 T」里找「红竖 T」，需颜色+朝向两特征，串行搜索，斜率陡）；目标字母再旋转 0°/45°/…/315° 八档测心理旋转。
- **自变量**：set size（4/8/12/16）、目标有无、搜索类型、旋转角度（8 档）。
- **因变量**：RT、正确率、搜索斜率、角度→RT 函数。
- **预测**：特征斜率≈0、联合斜率 20–40 ms/项；旋转角越大越慢，180° 最慢。

> 首批实测判定这一版**未跑通**，联合搜索目标旋转与目标定义互相冲突。收数前请先按「结果与讨论」里的三条建议改设计。

### 实验 2 · Stroop 效应
- **任务**：按字的显示颜色按键（红=F / 绿=G / 蓝=H），忽略字义。
- **自变量**：字义与颜色关系——一致 / 中性 / 冲突，各 18 题，混合随机共 54 题。
- **因变量**：各条件正确反应时中位数、错误率、超时率。
- **指标**：干扰 = 冲突 − 中性；促进 = 中性 − 一致。
- **预测**：冲突 > 中性 > 一致；干扰幅度大于促进。

### 实验 3 · 返回抑制（IOR）
- **任务**：盯中央「+」，某框短暂亮起后圆点出现在左框或右框，按空格键。
- **自变量**：位置关系（同侧 / 异侧）、线索-目标间隔（100 ms / 700 ms）。
- **流程**：80 有圆点题（4 条件各 20，左右各 10）+ 16 无圆点题（检查抢按）。
- **预测**：短间隔同侧更快；长间隔同侧更慢，「同侧 − 异侧」由负转正。

## 结果页呈现与数据导出

结果页给被试呈现三类信息：

1. **个体表现**：自己的效应量（干扰值、IOR 效应、搜索斜率、察觉报告等）。
2. **文献对照**：结合原始文献（Stroop 1935、Posner & Cohen 1984、MacLeod 1991 等）解释效应并附 DOI 链接。
3. **群体对比**：末尾自动追加「你 vs 全体被试」，把该被试核心指标与收数平台**其他所有被试的均值**实时对比，用 0 为原点的对比条形图呈现（支持负值）。会按被试码排除自己的记录。
4. **眼动分析**（勾选眼动时）：基于本机当次会话采集的注视点，做 I-VT 注视分类、质心偏移、AOI 热区。

数据查看/导出有三条路：结果页的本地 CSV 备份（`exportCSV`）、上传失败时的自动兜底导出、以及后台的两个导出按钮（见下节）。也可在收数平台 `/hw2` 自行下载。

## 结果与讨论（首批实测数据，截至 2026-11-08）

下面所有数字来自 2026-11-08 从收数平台拉回的三份原始记录：视觉搜索 5 人 × 96 试次、Stroop 6 人 × 54、IOR 6 人 × 96，合计 1380 试次。口径与网页一致，全部走 `js/stats.js`：先在被试内取正确试次的 RT 中位数，再对被试求平均，离散度报总体标准差（除以 n）。搜索斜率是 RT 对 set size 的最小二乘回归系数。

方向一致性用精确符号检验，但这里得先把话说清楚：n=5 时双侧符号检验能取到的最小 p 是 2/32 = 0.063，n=6 是 2/64 = 0.031。也就是说样本量为 5 的实验，结果再整齐也「显著」不了；那个 0.031 同样只是 n=6 的下限，不是多强的证据。下文引 p 值只为描述方向，不拿来裁决效应有无。这批数据的用途是检查范式有没有跑通、揪出实现里的毛病，不是下理论结论。

### 视觉搜索

预期是特征搜索斜率接近 0、联合搜索 20–40 ms/项。实测特征斜率 3.19 ± 8.85 ms/项（范围 −11.43 ~ 14.38）；
联合斜率 −2.74 ± 3.15，方向反了，五人里四人反应时负值。联合减特征 = −5.93 ± 7.72，3 负 2 正，符号检验 p = 1。
因为正确率先塌了：联合搜索 55.8 ± 9.6%，接近于几率水平，特征搜索正确率： 78.8 ± 13.4%。

把正确率按目标有无拆开，毛病就露出来了：

| 条件 | 目标出现 | 目标不出现 |
|---|---|---|
| 特征搜索 | 76.7%（92/120） | 80.8%（97/120） |
| 联合搜索 | 80.0%（96/120） | **31.7%（38/120）** |

按人看更直白：P02、P03、P04 在「联合·目标不出现」上的正确率是 8% / 0% / 0%，在「目标出现」上是 100% / 96% / 92%——这三个人几乎全程按同一个键；P01 反过来，倾向按「没有目标」。这不是搜索能力差，是**反应偏向**：任务难到无法判断时，人会退化成固定按键策略，正确率于是变成按键比例的镜像。P05 是另一副样子，96 个试次里 90 个 RT < 200 ms，两种条件正确率 54.2% / 58.3%，基本在快速乱按。用这种试次拟合出来的 −2.74 没有解释价值。更麻烦的是统计层把「目标出现」和「不出现」的正确试次混在一起算斜率，后者被反应偏向砍掉七成，各 set size 的构成也不再平衡；单独拆开，目标出现时联合斜率 0.76 ± 8.17，不出现时 −11.63 ± 21.58（P03、P04 连四个有效点都凑不齐）。

为什么难到这个地步？我怀疑是两个自变量互相拆台。联合搜索的目标定义为「红竖 T」，靠颜色加朝向两个特征区别于干扰；可同一批试次又把目标旋转 0°–315°。它和「红横 T」干扰在特征组合上不再有稳定区别，被试手里的判断规则直接失效。特征搜索只靠颜色区分，旋转不破坏规则，正确率因此还留在 79% 附近——这个对照恰好支持上面的解释。这个结果表明，实验设计过程中关于旋转的操纵可能是失败的

心理旋转的结果也不支持原有的更改预测假设。联合·有目标试次中，180° 的正确率 53% 。并且未呈现出旋转反应时随角度的变化规律，这可能因为字母T的旋转特征不明显，应当采用旋转字母R等存在明显空间形态变化的字母。



### Stroop：唯一一个方向一致、量级也合理的发现

三条件 RT 依次是一致 584 ± 90、中性 615 ± 128、冲突 699 ± 182 ms，顺序与经典结果对得上。干扰（冲突−中性）85 ± 69 ms，5/6 人为正；促进（中性−一致）31 ± 46 ms，5/6 人为正，两者符号检验都是 p = 0.219。
**干扰大于促进**的效应稳定显著：差值 54 ± 34 ms，六个人无一例外（p = 0.031）。错误率给出相似的证据：一致 3.7%、中性 3.7%、冲突 14.8%（16/108），超时 0 次，总错误 24/324。用中性汉字把干扰和促进拆成两个量是做对了——如果只报常见的「冲突−一致」115 ms

从被试层面的数据分析来看：P03 的冲突 RT 只有 422 ms，比自己的一致条件（492 ms）还快，干扰 −26 ms，可他冲突错了 5/18，错答 RT 中位 385 ms：典型的提前抢答、蒙对一部分。P04 正相反，冲突 1003 ms、干扰 207 ms、错 7/18，走的是慢而谨慎的路线。两个人处在速度–准确性权衡的两端，却都以各自的方式指向「冲突更难」——一个靠错误率，一个靠 RT。这也暴露了只取正确试次算中位 RT 的偏向：冲突条件剔掉的 16 个错误里不少是快错的，剩下的正确试次会系统性偏慢，干扰量因此可能被高估。P06 零错误、干扰 106 ms，表现出较为稳健的效应。

按 MacLeod（1991）综述里按键版 Stroop 的常见量级，干扰一般 50–100 ms，这批 85 ms 落在区间内；促进小于干扰，也符合「字义自动激活造成的冲突强于一致带来的助力」这一解释。

### IOR（返回抑制）

长间隔的「同侧−异侧」是 +31 ± 38 ms，5/6 人为正；短间隔 +2 ± 20 ms，两者相差 29 ± 30 ms。只盯着这三个数，很容易写成「700 ms 出现返回抑制」。
每一个组合的反应时分布如下所示：
| | 同侧 | 异侧 |
|---|---|---|
| 短间隔 100 ms | 366 | 363 |
| 长间隔 700 ms | 358 | **323** |

同侧从短到长只快了 8 ms，几乎没动；异侧快了 40 ms。同时全体 RT 从短间隔的 365 ms 掉到长间隔的 339 ms。
换句话说， +31 ms 的差值主要来自**异侧在长间隔变得特别快**，而不是同侧被抑制得变慢。Posner 与 Cohen（1984）说的返回抑制，机制上应当是注意从线索位置撤出、同侧目标的加工变差；这里看到的更像随等待时间延长的一般性准备效应（foreperiod），叠加一个异侧的相对优势。短间隔也没出现预期的早期易化（+2 ms，p = 0.688）——100 ms 这个 SOA 可能已经滑出外源性线索的易化窗，或者 50 ms 的边框闪亮本身不足以定向。

这部分的数据质量反而是三个实验里最好的：96 个无圆点试次只出现 1 次虚报（1.0%），说明被试确实在等圆点而不是见框就按；抢按 23 次，量级可接受。唯一反例是 11-04 那次预试的 P01，长间隔差值 −34 ms、交互 −16 ms，同时 SOI 主效应达到 −81 ms（其余五人都落在 −24 ~ +18）。这份记录更像参数还没调稳时的试跑，正式统计时该单独标注或剔除，但现在它和其他五份一起进了群体均值。

要往下做，把 SOA 扩成 100 / 300 / 500 / 700 四档画出线索效应的时间曲线，别用两点连一条线；再加一个「无线索」基线，才能把「同侧变慢」和「异侧变快」分开——这是当前设计最缺的一格。

### 跨实验的三个坑

**顺序没平衡。** 五个会话全是同一个顺序，练习／疲劳效应和实验类型完全混淆。视觉搜索总是第一个，它数据最差这件事至少有一部分可能来自「刚坐下还没进入状态」；但也不能拿顺序当挡箭牌——联合搜索 31.7% 的目标缺失正确率是反应偏向，疲劳解释不了。3×3 拉丁方就能把这个混淆拆掉。

**功效不足。** n=5~6 时符号检验的下限就卡在 .063 / .031，任何「不显著」都不能读成「没有效应」。后续试验应当扩大被试量，在大样本（n≥30）情况下讨论被试的稳定效应。

**眼动数据部署。** 由于模型部署等原因，本实验的眼动校准质量不高，因此仍需要结合Eyelink桌面眼动仪等专业设备，或者是改良眼动模型校准提高眼动精度，获取眼动数据，依次结合眼动状态进行更细致的分析。
